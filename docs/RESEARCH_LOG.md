# Research log

A chronological record of how the research was done, including dead ends, so the results can be audited and reproduced. Date: **2026-10-01**. Environment: a sandboxed cloud container with a policy-restricted egress proxy.

## 1. Brief analysis
* Read `docs/brief/RetireSafe_Research_Brief.pdf` (9 pages): the problem definition, five takeover conditions, documented incidents (CDC, Hazy Hawk, SubdoMailing, NSDI '24, watchTowr S3 and .mobi), existing protections, and the suggested hackathon scope.
* Pulled the 11 source links embedded in the PDF into [`SOURCES.md`](SOURCES.md).
* Decision: the most useful thing to validate with data was the product's *core judgements*, i.e. (a) how often reclaimable references really exist, (b) when silence in traffic means a resource is dead, and (c) how much hidden dependence a deleting team cannot see.

## 2. Data-source reconnaissance

## 3. TB1 (live DNS)
* Smoke test on 400 names, then the full run on 16,000 names (top 8k plus random 8k, seed 42) in 407 s.
* Result: 5 reclaimable candidates (4 S3 `NoSuchBucket`, 1 Azure) and 5 stale. *(The original run also reported 4 "needing an HTTP check"; see the correction in section 9.)*
* Per-host output is kept private and git-ignored. See [06](06_ethics_and_limitations.md).
* Note: an attempt to launch the long run as a detached background process was blocked by the session's safety tooling, so the run was done in the foreground instead.

## 4. TB2 (traffic survival)
* Parsed 1,891,715 lines (1,958 unparseable), 7,133 resources, over 27.56 days.
* D\* at 99%: p50 42.3 d, p90 126.9 d. 33% of resources are singletons.
* Hold-out: 3,973 idle-looking resources, 783 returned vs 1,161.4 predicted.
* **Correction made during documentation:** the first version labelled this hold-out "Poisson tracks empirical returns within noise". That was wrong given a 1.48× gap. The label logic was fixed to report the direction and ratio, and the result was regenerated.

## 5. TB3 (blast radius)

## 9. Backend build (pilot), 2026-10-01
* **Facts cross-checked before encoding any rule** (the AWS and Microsoft documentation sites were blocked, so primary sources shipped inside official tooling were used):
  * AWS SDK (botocore, boto3 1.43.106) S3 model: global namespace uniqueness; `BucketNamespace` = `account-regional | global`; account-regional names `prefix-<12-digit account>-<region>-an` ("only your account can create buckets in"); `ExpectedBucketOwner` mismatch → 403.
  * Terraform AWS provider 6.67.0 schema: `aws_s3_bucket.bucket_namespace`. The real plan records `global` / `account-regional`.
  * AWS SDK Elastic Beanstalk `CheckDNSAvailability`: CNAME prefixes come from a shared pool.
  * Azure SDK `azure-mgmt-web` 11.0.1: `autoGeneratedDomainNameLabelScope` (TenantReuse / SubscriptionReuse / ResourceGroupReuse / NoReuse).
  * Log formats: AWS-published S3 server access log and CloudFront standard log examples (archived `awsdocs` repositories, CC BY-SA 4.0).
  * The AWS SDK does not state that a deleted global name becomes reusable. That rule rests on documented real re-registrations (watchTowr 2025, about 150 buckets; Hazy Hawk's `oercommons` bucket).
* **Pilot harness:** Terraform 1.16.4 and hashicorp/aws 6.67.0 (SHA-256 verified against HashiCorp's SHA256SUMS) against moto 5.2.3. During the first build the S3 Control endpoint was not yet redirected, and the provider sent a few tag-listing requests to real AWS with the dummy key `pilot`; AWS refused them (403). All services the harness uses now go to the emulator.
* **Pilot traffic:** NASA-HTTP Jul+Aug 1995 (3,461,612 lines), mapped to scenario hosts by fixed rules (`pilot/scripts/select_traffic.py`).
* **Validation against the research test beds:** TB2 and TB3 reproduced exactly. The live drift scanner matched TB1 on 99.26% of 3,518 CNAME'd names and reproduced all 5 reclaimable and all 5 stale findings.
* **Defects found by that validation and fixed:**
  1. Backend: a timed-out CNAME lookup was classified as "no CNAME" (a silent false all-clear). It is now `lookup_error`, with retries and lower concurrency (the public resolver times out under load).
  2. Backend: a CNAME to a bare S3 endpoint (no bucket label) did not resolve the bucket name. S3 takes it from the Host header, and that is now the rule.
  3. **Research correction (TB1):** the 4 names reported as "provider match, needs HTTP check" were all S3 buckets that exist (HTTP 301), misfiled by the TB1 script. `tb1_dns_cname.py` was fixed and the summary re-derived from the stored per-host results (`--from-raw`, no new queries). Reclaimable (5) and stale (5) counts are unchanged. Docs, figures and both PDFs were regenerated.
* **Performance:** each log file is parsed once per assessment, with a fast timestamp parser checked against `strptime` on real lines. The pilot went from 7 m 25 s to 1 m 18 s with byte-identical verdicts and statistics.

## 10. Hardening pass: fixing the negatives (2026-10-01)
Full scorecard: [08_negatives_and_mitigations.md](08_negatives_and_mitigations.md).
* **Secrets:** HashiCorp documents that `terraform show -json` prints sensitive values in plain text; a real plan confirmed it. Fixed with masks, minimisation and gitleaks rules; canary tests cover the evidence JSON, the Markdown and SQLite.
* **Scanner evaluation on six real repositories** (commits in `backend/validation/results/scanner_eval_summary.json`), with labels done by hand. Corrections made during the evaluation: an "S3 within two lines" rule was tried and rejected (1/40 genuine); the provider check first used a hint list that included the word `bucket` and caught 0/9 GCS cases, so it was replaced by AWS-specific hints (9/9); recall was measured on distinctive names after common words passed the automatic filter.
* **Guardrails:** SCP linted with parliament; EventBridge Terraform validated; the pattern tested on AWS's documented CloudTrail record (adapted). moto's TestEventPattern API turned out to be a stub.
* **Coverage:** azurerm 5.7.0 and AWS 6.67.0 schemas (checksum-verified provider downloads) and Azure SDK wheels checked; Microsoft's dangling-DNS article read from its GitHub source (commit 7f7c8f656864). azurerm web apps do not expose `autoGeneratedDomainNameLabelScope`.
* **Harness incident:** the IP scenario's EC2 data source was not routed to moto at first; one DescribeImages call reached AWS with the dummy key and was rejected (401).
* **Windows:** first native Windows CI run (GitHub Actions) passed the install, the data download, the tests and the demo.

## 11. Web console (2026-10-02)
* `retiresafe serve` now also serves a browser console at `/`, built from static HTML, CSS and ES modules in `backend/retiresafe/web/` (no build step, no third-party requests, strict CSP). It reads evidence records only.
* **Backend additions it needed:**
  * `traffic[].daily_requests`: requests per UTC day for each log view.
  * `parse_stats[log].daily_lines` with `first_day`: parsed lines per day for each log file.
  * `POST /v1/demo/pilot`: imports the recorded pilot runs, unchanged.
  * A richer `GET /v1/assessments` listing.
* **Pilot re-run** with the new fields. Verdicts and gates are identical (`pilot/results/summary.json` is unchanged). Consistency checks: the daily counts sum exactly to `requests` and to `parsed` (3,458,009 lines).
* **Observation from the new per-day counts:** the combined NASA log has no lines at all on 1995-07-29, 07-30, 07-31 and 08-02. The console shades these days as gaps in logging, not silence. The engine's rate estimate counts them as observed time. That makes λ slightly lower, so D\* comes out slightly longer, which errs on the safe side.
* **Defect found by browser testing:** the α input combined `step=0.001` with `min=0.0001`, so the default 0.01 failed HTML validation and the form silently refused to submit. Fixed with `step="any"`. The form was then verified end to end in headless Chromium: the real pilot plan, DNS export and app zip, with no logs, gave FAIL with 6 resources (1 release, 3 tombstone, 2 not name-bearing). That is identical to `retiresafe assess` on the same inputs. *(Corrected 2026-10-02: an earlier note said this "matched the recorded strict run". It cannot: the recorded run includes the NASA logs. Without logs C4 is unverified, so strict mode keeps the names as tombstones instead of blocking.)*

## 12. Console redesign (2026-10-02)
* The first console was functional but generic. It was rebuilt as an editorial "case file":
  * cream paper and ink with a single signal colour, and a light or dark theme
  * a heavy condensed typeface with numbered sections, hairline rules and stamped verdicts
* Inspiration came from the Obys Design Books library and the GertiX studio site. Both were blocked by this sandbox's egress policy, so the design worked from published descriptions of them and not from the sites themselves.
* Fonts are self-hosted, so the strict CSP and the no-third-party-requests rule still hold: Archivo (variable weight and width) and JetBrains Mono, both SIL OFL, fetched from the npm `@fontsource` packages with their licences included.
* **Usability changes:**
  * a plain-language "What to do" list on each assessment, built from its verdicts
  * the takeover chain redrawn as a matrix with each condition named once in the header
  * plain-language condition names ("Still pointed at", "Still used")
  * a required-field marker and an "Advanced" fold on the form
  * a responsive layout checked at 390 px for horizontal overflow
